# 더배움 영수학원 — 교재비 납부·SMS 알림 관리 시스템 (2단계 프로토타입)

학생/교재/청구/입금/미납/SMS발송/설정까지 전체 흐름을 실제로 동작시켜볼 수 있는 프로토타입입니다.
SMS 발송과 입금 자동매칭은 **실제 외부 API 연동 없이 시뮬레이션(DB 로그 기록)으로 동작**합니다. (3단계에서 실연동 예정)

## 기술 스택
- Node.js + Express
- SQLite (Node 22 내장 `node:sqlite`, 별도 설치 불필요)
- EJS (서버사이드 렌더링) + 순수 HTML/CSS/JS
- 세션 기반 관리자 로그인 (bcrypt)

## 처음 실행하는 방법

```bash
# 1. 패키지 설치
npm install

# 2. 가짜 데이터 시딩 (학생 70명, 교재 18종, 청구 130여건 등 생성)
npm run seed

# 3. 서버 실행
npm start
```

브라우저에서 `http://localhost:3000` 접속.

> ⚠️ `data/app.db`는 git에 포함되지 않습니다(.gitignore). 클론 후 반드시 `npm run seed`를 먼저 실행해야 데이터가 생깁니다.
> `npm run seed`는 기존 데이터를 모두 지우고 새로 채우므로, 직접 입력한 데이터가 있다면 재실행 시 사라집니다.

## 로그인 정보 (시딩 데이터 기준)

| 구분 | 아이디 | 비밀번호 |
|---|---|---|
| 원장 | `director` | `director123` |
| 직원 | `staff1` | `staff123` |

> ⚠️ 위 계정/비밀번호는 데모용입니다. 실제 운영 데이터로 전환할 때는 반드시 비밀번호를 변경하세요(설정 메뉴에서 변경 가능).

## 폴더 구조

```
src/
  app.js              # 진입점
  db/
    schema.sql        # 테이블 정의
    seed.js           # 가짜 데이터 생성 스크립트
    index.js          # DB 연결
  routes/             # 메뉴별 라우터
  services/           # SMS 발송, 입금매칭, 미납배치 로직
  views/              # EJS 템플릿
public/               # CSS, 이미지
data/
  app.db              # SQLite 파일 (git 추적 안 함)
  uploads/            # 거래내역 업로드 임시 폴더 (처리 후 자동 삭제)
```

## 메뉴 구성

1. **대시보드** — 이번 달 청구/수납 현황, 미납 현황 요약
2. **학생 관리** — 등록/수정/퇴원처리(소프트삭제), 검색·필터
3. **교재 관리** — 등록/수정/비활성화, 과목별 필터
4. **청구 관리** — 학생+교재 선택해 청구 생성, 생성 시 안내 SMS 발송(시뮬레이션)
5. **입금 관리** — 은행 거래내역(.xlsx/.csv) 업로드 → 컬럼 매핑 → 자동매칭 → 수동매칭
6. **미납 관리** — 입금기한 초과 자동감지, 개별/다중 미납 안내 발송
7. **SMS 발송 로그** — 전체 발송 이력, 성공/실패 통계, 실패건 재발송
8. **설정** — 학원 계좌정보, SMS API 키(저장만, 미연동), 문자 템플릿, 비밀번호 변경

## 입금 거래내역 업로드 시 주의사항

은행 거래내역 파일은 보통 "입금자명"이 별도 컬럼으로 없고, **거래내용/거래기록사항 컬럼에 입금자 정보가 섞여 들어옵니다**
(예: "학생이름+학교+학년" 형식). 컬럼 매핑 화면에서:

- **입금자 식별 열**: 거래내용 또는 거래기록사항 컬럼을 선택
- **입금금액 열 / 출금금액 열**: 분리되어 있는 경우 둘 다 매핑하면 출금 거래(이체/수수료 등)는 자동으로 제외됩니다

자동매칭 우선순위: ① 학부모 전화번호 뒷4자리 포함 → ② 학생이름 포함 → ③ 학부모이름 포함 (모두 잔액과 금액이 정확히 일치해야 자동확정)

## 알려진 제약사항 (3단계 예정)

- `node:sqlite`는 Node 22의 실험적 기능입니다. 운영 전환 시 `better-sqlite3` 등 정식 드라이버로 교체를 권장합니다.
- 입금 파일 업로드 시 컬럼 매핑 데이터는 메모리에 임시 보관되며(5분 후 자동 삭제), 서버 재시작 시 사라집니다.
- 미납 자동전환은 미납 관리 화면 진입 시 실행됩니다. 운영 환경에서는 cron 등으로 매일 배치 실행하는 방식으로 바꾸는 것을 권장합니다.
- 신규 관리자 계정 생성/삭제 기능은 아직 없습니다 (설정 화면에서 비밀번호 변경만 가능).
- 한 건의 입금이 여러 청구에 걸쳐 분배되는 경우(예: 형제 합산입금)는 아직 지원하지 않습니다.
